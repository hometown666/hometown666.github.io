TxtTunnel 落地计划

手机 ↔ 本机 Cursor IDE：AHK 写入前台聊天框 + agent-transcripts JSONL 伪流式读取。
目录：TxtTunnel/ · 依赖：../AutoHotKey（listener）、../remote_control（Tailscale）

阶段：核心遥控链路与增强能力已落地，现处于持续打磨；打包见 §8；想法池见 §6.5。
修订：2026-09-08 — 叙事脱离 MVP；压缩已完成工具详规；新增 §8 打包 / §8.0 listener 归属；§6.5 想法池 I1–I9；§6.3 含 F4 手测清单。

详规外置（改接口 / AHK 前先改文档）：

文档内容

docs/ahk-cursor.md快捷键、切换、Fork、排错
docs/transcript-format.mdjsonl 裁剪规则

1. 定位

项决定
主路径IDE 伪同步：AHK + JSONL 轮询/SSE
副路径Cursor agent CLI（/api/cli/*，会话库独立）
非目标像素级桌面镜像、dsh 皮肤/宠物、改 Cursor 源码、官方 API
心智写只打 IDE 前台会话；读可按 uuid 监视任意历史

主用户流：Tailscale 打开手机 Web → 会话列表 → 进聊天 → 发送 → poll/stream 看到 assistant / 工具步骤 → turn_ended 表本轮结束。

不承诺：逐 token 流式、CLI 与 IDE 同列表、Cursor 改版零维护、锁屏/未登录桌面可用。

2. 架构

原则：前端不直接写 command.txt；Gateway 负责排队、超时、鉴权、路径解析。

技术栈：Gateway Node 20+ TS（Hono）· Web Vite + React · AHK v2 listener · 鉴权 Tailscale + 可选 Bearer / 配对 cookie。

3. 数据路径

工作区路径编码为 projects 子目录，例：D:\…\control test → d-Temp-control-test。

配置优先：CURSOR_PROJECT_DIR 写死 slug 目录；多工作区见 POST /api/projects/active。

会话列表字段（GET /api/ide/sessions）：

  • preview：jsonl 前 48KB 内首条 user 前 80 字（≠全文）。
  • title：可选，来自 composer.composerHeaders。
  • 全文搜索走 GET /api/ide/sessions/search?q=，不把 haystack 塞进列表。

消息读：按行 parse；坏行跳过；user/assistant 气泡 + turn_ended + 工具折叠；增量用 fromLine / SSE。裁剪见 transcript-format.md。

4. 会话身份（最关键）

矛盾：AHK 只操作前台聊天框，不带 sessionId；jsonl 按 uuid 分文件。无官方共同主键 → Gateway 绑定层。

原则说明
权威身份jsonl 目录名 uuid
AHK 无身份发送后用指纹（user 文本）确认落在哪个 uuid
不能遥控打开 uuid无 open(sessionId) API；切换靠时钟浮层标题过滤
sessionId 请求字段期望校验，不是「请写入该会话」

发送闭环（POST /api/ide/send）：

  1. 快照各 jsonl size/mtime → AHK focus + paste + Enter
  2. 超时内找「变大且含 fingerprint 的 user 行」→ 写入 activeBinding
  3. 未命中 → unbound: true；落在别处 → SESSION_MISMATCH（不改绑）
  4. newChat: true → 发送前不存在的新 uuid 优先

GET /api/ide/active 返回当前绑定。详见 docs/ahk-cursor.md。

AHK 命令（listener）：cursor:focus · cursor:send* · cursor:switch · cursor:new · cursor:fork · 长文只走剪贴板。

6.3 Fork / 单标签（已实现 · 待手测）

不变量：操控后的 Editor Agent 聊天区，打开的 composer 标签数 ≤ 1。
主路径：唯一标签上右键 → ↓×N（默认 5，.env FORK_MENU_DOWNS）→ Enter → waitForNewComposerHeader → 原会话 DB 改名 -base。
废弃：More … 键入 Fork 作主路径。
关邻签：仅在「绑定 / switch」路径；Fork / new-chat 不加多余 Ctrl+F4（只剩 1 标签时 F4 会拆掉 Agent 侧栏）。

本机快捷键（kakyo）：Toggle Agent = Ctrl+Alt+J · Agents Window = Ctrl+Alt+U（非目标）· 关聊天标签 = Ctrl+F4 · 新会话 = Ctrl+N。

切片进度：F0–F3 ✅ · F4 手测 ☐（步骤见下）。详操作与坐标见 docs/ahk-cursor.md。

F4 手测计划（本机 · 可勾选）

目标：证明「标签右键 Fork」主路径可用，且 不会因多余 Ctrl+F4 拆掉 Agent 侧栏。
入口：聊天页 Fork → POST /api/ide/fork（必要时无 F4 的标题切换 → cursor:fork → 可选 palette → 原会话 -base → 绑定 fork）。

前置

  • Gateway + listener.ahk 已跑；改过 listener / 坐标后已重载
  • 设置里 fork_tab_x/y 已按本机标定（可先用 WindowSpy 点标题栏唯一聊天标签中心）
  • .env：IDE_SWITCH_SESSION=1；FORK_MENU_DOWNS 与本机右键菜单「Fork」项一致（默认 5）
  • 待测会话在 Composer 里已有非空标题（非 New Chat）；记下原标题 T

准备 IDE 表面

  • Editor Agent 打开（Ctrl+Alt+J）；确认不是 Agents Window（Ctrl+Alt+U）
  • 聊天标签尽量 只留 1 个（多标签时先手动收敛，或先「绑定」一次让 converge 关邻签）
  • 手机/本机 Web 打开该会话页；可选先点一次「绑定」确认能进对本会话

主路径 A — 已在前台的唯一标签

  1. 点 Fork，等提示「已 Fork → …」
  2. 看响应/提示：ahkPath 应为 tab-menu（若写「已用命令面板重试」则主路径失败，记为 A′）
  3. Agent 侧栏仍在（整栏没被关掉）——本项失败即 F4 回归不过
  4. IDE：出现 fork 会话，标题多为 (1) T（或带数字前缀）
  5. IDE / 列表：原会话标题变为 T-base（renamed: true；失败则记 renameError，fork 仍可算半成功）
  6. Web 自动跳到 fork 会话；GET /api/ide/active（或发一句 ping）落在 fork uuid
  7. 在 fork 里发一条短消息，10s 内 jsonl / 气泡能看到 —— 证明绑的是可写前台

主路径 B — 先绑别的会话再 Fork（测「Fork 前无 F4 切换」）

  1. Web 打开会话 X，点「绑定」；确认 IDE 前台是 X（绑定会 converge，侧栏应仍在）
  2. 不关页，直接 Fork
  3. 同上验收 3–7；switched 可为 true；Fork 过程中不应再对唯一标签乱 F4

对照 / 失败时

现象先查
无新 composer / SWITCH_FAILEDfork_tab_*、↓ 次数、菜单是否还有 Fork；看是否落到 palette-retry
Agent 整栏消失是否误开 converge；确认 Fork 代码路径无 converge-tabs；Ctrl+Alt+J 重开后再测
标题撞车 / assumedForeground原标题与 (1) … 过滤冲突；先改名或接受「请确认电脑已打开本页会话」后手测前台
跳到 fork 但发送进错会话绑定未更新；看 activeBinding / 再绑一次

通过标准（勾 F4）

  • A 全绿，且至少一次 ahkPath=tab-menu
  • Agent 侧栏在 Fork 前后保持打开
  • 原会话 -base、fork 可发送
  • （建议）B 也过一遍

通过后把上表勾完，并将本节「F4 手测 ☐」改为 ✅，日期记在 §6.4。

8. 打包路线（现在 → 可分发）

目标：别人（或未来的自己）用安装包 / 便携目录拉起，而不是先读仓库 README 手工配路径。
裁决：继续用 AHK 文件桥；不把「listener 改 HTTP」当作打包前置。打包痛点是双进程 + 路径 + 首启标定，不是 command.txt。

8.0 Listener 归属（裁决）

AutoHotKey\listener.ahk 是桌面遥控底座（SSH / focus: / shell: / runlog: 等 + TxtTunnel 的 cursor:* / screenshot），约 1900 行，不是 TxtTunnel 私有组件。

场景决定
日常开发不搬整棵进 TxtTunnel/。真源仍在 ../AutoHotKey；.env 的 AHK_DIR 指向它；与 SSH 遥控共用同一 listener 进程
打包 / 发布安装根内必须带一份能跑的 listener（整份拷贝，或裁剪为文件桥 + cursor:* + screenshot + 坐标）。用户机不假设还有 AutoHotKey 仓
改协议 / 快捷键仍改 AutoHotKey 真源，并同步 docs/ahk-cursor.md；发版时再拷进发布物（避免两份长期分叉却不更新）
以后若拆模块可选：core（通用）+ cursor（TxtTunnel）；属重构，不作为当前打包前置
明确不做为进 TxtTunnel 仓而切断 SSH 文件桥；为打包先把 listener 改成 HTTP

操作细节（命令表、标定、排错）留在 docs/ahk-cursor.md，PLAN 不重复。

P1.2trigger 默认同机默认 %LOCALAPPDATA%\TxtTunnel\ahk_trigger；仍可用 env 覆盖；安装时 mkdir
P1.3AHK_DIR 相对根发布物内嵌 listener 副本（§8.0）；开发机续用 ../AutoHotKey。可整份拷或裁剪 cursor:* + screenshot
P1.4工作区 / projects安装后首次：自动列 %USERPROFILE%\.cursor\projects 或要求选 WORKSPACE；避免把开发机路径写进模板
P1.5配置模板仓库保留 .env.example（无隐私）；安装生成 .env（gitignore）

验收：换一台同账号结构的 Windows，只改少量路径（或零改）能起 Gateway + listener。

8.5 P2 — 一键安装

单入口（建议）：scripts/install.ps1（或日后安装程序调它）。

卸载：停进程 · 删 Startup 项 · 可选删安装根（保留用户 .env / coords 需确认）。

8.6 P3 — 首启向导（产品化）

设置页或独立 /setup：

检查通过标准
Listenerstatus.txt 新鲜且 listener=ok
Cursor进程在跑（或提示用户打开）
点击坐标click_coords.txt 存在且非空；提供现有编辑 UI
网络显示本机访问 URL；提醒仅 Tailscale / 受信网
配对可选开启 REQUIRE_PAIRING + 展示扫码步骤

未通过不拦死高级用户，但默认高亮「还不能稳发消息」。

8.7 P4 — 发布物

形态内容适用
便携 zip预 build web/dist + gateway 源码或精简运行目录 + listener + install.ps1 + 短文档先做；迭代快
安装程序同上 + 向导选目录/自启勾选给非开发用户

版本：与 git tag / package.json 对齐；发布说明写清依赖 Cursor 版本敏感（快捷键/坐标可能要重标定）。

8.8 P5 — 可选（不阻塞 P4）

  • Gateway 打成单文件，减少「系统 Node 版本」摩擦
  • 代码签名，降 SmartScreen
  • 自动更新通道
  • AHK HTTP 双通道（运维更干净；非打包必需）

8.9 建议顺序（与 §6 的关系）

不做：为打包先重写 listener IPC；在未稳定发送/切换前做安装程序炫技。

附录：已验证事实

  • IDE 历史在 agent-transcripts\*.jsonl，可轮询。
  • agent ls 不含 IDE 会话；CLI 在 ~/.cursor/chats。
  • AHK 文件桥 C:\ahk_trigger + listener 已成熟；打包时目录可迁 AppData，协议不变。
  • 主路径 = AHK 写 + JSONL 读 + Gateway + 手机 Web；CLI 为旁路。
