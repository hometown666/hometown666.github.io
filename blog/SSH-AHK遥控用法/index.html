SSH 遥控桌面（AHK 文件桥）用法

SSH 会话与桌面会话隔离，不能直接点 GUI。做法是：SSH 往 C:\ahk_trigger\command.txt 写一条指令 → 桌面里常驻的 listener.ahk 执行 → 读 last_result.txt / instances.txt 拿结果。

日常请用前置库，不要手写 echo ... > command.txt + 固定 Sleep 3。

Shell 前置库 调用方式
CMD / Termius ahk.bat call C:\ahk_trigger\ahk.bat <子命令> ...
PowerShell ahk.ps1 先 . C:\ahk_trigger\ahk.ps1，再调函数

1. 一次装好

本机（桌面会话）

  1. 已登录交互桌面（不要只开 SSH、桌面未登录）。
  2. 已运行 AutoHotKey\listener.ahk（建议放进「启动」或登录任务计划）。
  3. OpenSSH 能登录该 Windows 用户。C:\ahk_trigger\ 由 listener 自动创建。

复制前置库到触发目录（本机做一次；路径按仓库改）：

wait_result.bat 仅为兼容旧写法，内部转调 ahk.bat wait。

控制端登录：

登录后可能是 cmd 或 PowerShell，下面按任务对照写。

2. 推荐工作流（最短路径）

  1. SSH 登录。
  2. 加载前置库（见下表）。
  3. （可选）设快捷方式目录：PROG_DIR / Set-AhkProgDir。
  4. 确认 listener：status。
  5. 启动：lnk wechat → 看回传里的 slot=。
  6. 双开后再 instances；用 focus / click / close / kill 操作对应 slot。
步骤 CMD PowerShell
加载库 直接 call C:\ahk_trigger\ahk.bat ...（可选 doskey ahk=call C:\ahk_trigger\ahk.bat $*） . C:\ahk_trigger\ahk.ps1
设程序目录 set PROG_DIR=D:\Users\Desktop\程序 Set-AhkProgDir 'D:\Users\Desktop\程序'
设 AHK 脚本目录 set AHK_DIR=D:\试炼之地\Temp\control test\AutoHotKey Set-AhkDir 'D:\试炼之地\Temp\control test\AutoHotKey'
探活 call C:\ahk_trigger\ahk.bat status Invoke-AhkStatus

库内会等到 last_result 不是 PEND| 再返回；勿只靠 timeout /t 3 / Start-Sleep 3（微信绑窗常要数秒）。

3. 按任务查命令

以下默认已设好 PROG_DIR（或 PS 里 Set-AhkProgDir）。CMD 一律 call C:\ahk_trigger\ahk.bat ...；若已 doskey ahk=...，可写成 ahk ...。

启动程序

做什么 CMD PowerShell
跑 exe call ...\ahk.bat run notepad.exe Invoke-Ahk 'notepad.exe'
跑快捷方式 call ...\ahk.bat lnk WeChat Invoke-AhkLnk WeChat
提权 call ...\ahk.bat admin lnk Airmouse Invoke-AhkLnk Airmouse -Admin
双开 连续两次 lnk WeChat，再 instances 同上 + Get-AhkInstances
跑仓库里的 .ahk call ...\ahk.bat script auto_pickup Invoke-AhkScript auto_pickup

路径约定：快捷方式 = %PROG_DIR%\%名%.lnk；脚本 = %AHK_DIR%\%名%.ahk。会话变量只对当前 SSH 有效，重连要再 set / 点源。

Termius 不要多行粘贴「伪函数」；一律写成单行 call C:\ahk_trigger\ahk.bat ...。

查状态 / 实例

做什么 CMD PowerShell
刷状态 call ...\ahk.bat status Invoke-AhkStatus
看实例表 call ...\ahk.bat instances Get-AhkInstances
直接看文件 type C:\ahk_trigger\status.txt （库已处理编码）

按 slot 操作窗口

先从启动回传的 slot= 或 instances 拿到名字（如 wechat#1）。不要用裸 taskkill /IM Weixin.exe 关双开（会全灭）。

做什么 CMD PowerShell
激活 call ...\ahk.bat focus wechat#1 Invoke-AhkFocus wechat#1
点击（Window 坐标） call ...\ahk.bat click wechat#1 140 520 Invoke-AhkClick wechat#1 140 520
软关 call ...\ahk.bat close notepad#1 Invoke-AhkClose notepad#1
硬关 call ...\ahk.bat kill wechat#2 Invoke-AhkKill wechat#2
提权硬关 call ...\ahk.bat admin kill wechat#1 Invoke-AhkKill wechat#1 -Admin

桌面会话带日志执行（runlog）

runlog 在桌面会话里异步跑一条命令：listener 立刻回传 OK|...|spawned|pid=...，不阻塞后续 command.txt；stdout/stderr 进 .log，命令真正结束后 wrapper 才写 .exit。SSH 侧没有单独的 log 子命令。

不入实例表，status / instances 也不会出现 jobN。要 focus / kill / slot，请用 run / lnk / script。

做什么 CMD PowerShell
普通（短命令） call ...\ahk.bat runlog dir C:\ Invoke-AhkRunLog 'dir C:\'
指定 job 名 call ...\ahk.bat runlog job9 whoami Invoke-AhkRunLog 'whoami' -JobId job9
提权 call ...\ahk.bat admin runlog whoami Invoke-AhkRunLog 'whoami' -Admin
加长等 .exit 见下 Invoke-AhkRunLog '...' -TimeoutSec 120

文件约定（均在 C:\ahk_trigger\jobs\）：

文件 含义
<id>.log 命令 stdout + stderr（控制台编码，非 UTF-16）
<id>.exit 完成信号：一行退出码（控制台编码）。0 成功；未出现 = 仍在跑

时序

  1. listener 受理 → last_result 很快变成 OK|...|runlog|jobN|spawned pid=... log=...（不是等命令跑完）。
  2. 前置库再轮询 .exit（默认最多 15 秒），有则打印 --- log --- / --- exit ---。
  3. 超时仍无 .exit：打印当前 .log（若有）并提示稍后手动 type；桌面命令继续跑，listener 不卡。

常驻服务（gateway / hexo / npm start）——约定

做法 说明
❌ runlog ... && npm start 进程不退出 → 永远无 .exit；虽不卡 listener，但不适合当「启动服务」
✅ shell（推荐） 开可见 cmd 入表 shell#N，再粘贴常驻命令；可用 close/kill（杀进程树）
✅ runlog + start 立刻返回 例：runlog job3 cmd /c "cd /d D:\path && start \"\" npm start" → 很快有 .exit，但无 slot、输出不进本次 log
✅ run / lnk / 专用 bat 需要 GUI 或已有捷径时

注意

  • 完成只看 .exit；不要指望结束后再改写 last_result（避免覆盖后续命令）。
  • 无「中断 runlog」子命令；runlog 起的进程用任务管理器；常驻请用 shell + kill。
  • 省略 job 名时 CMD 用 jobid.txt 自增；PowerShell 用 $script:AhkJobId。

常驻服务：桌面 CMD 壳（shell）

适合 gateway / npm start 等不退出的进程：先开可见控制台并入实例表，再往里粘贴命令；listener 不阻塞。

做什么 CMD PowerShell
开壳（入表） call ...\ahk.bat shell Invoke-AhkShell
提权开壳 call ...\ahk.bat admin shell Invoke-AhkShell -Admin
往壳里执行 call ...\ahk.bat shell shell#1 "cd /d D:\path && npm start" Invoke-AhkShell -Slot shell#1 -Command 'cd /d D:\path && npm start'
软关 / 硬关 close shell#1 / kill shell#1 Invoke-AhkClose / Invoke-AhkKill

典型流程：

注意

  • 命令在壳里直接跑，不要再套 start "" ...（会脱离控制台，slot 杀不干净）。
  • 喂命令靠剪贴板粘贴 + Enter；中文路径走前置库即可。
  • 日志回传暂不做：需要时在命令里自带重定向，例如 npm start > C:\ahk_trigger\jobs\gw.log 2>&1，SSH 侧再 type。
  • kill 现为 taskkill /F /T（进程树）；close 关控制台窗，通常也会带走挂在该控制台下的子进程。

4. 前置库速查

ahk.bat 子命令

子命令 作用
wait [秒] 等到 last_result 非 PEND 并打印
send "命令" / run <路径> 写 command.txt 并等待
lnk <名> 启动 %PROG_DIR%\名.lnk
admin lnk|run|kill|runlog|shell ... 提权变体
status / instances 刷状态 / 看实例表
focus|close|kill <slot> 按 slot（kill 含进程树 /T）
click <slot> <x> <y> 点击（与 WindowSpy Window 坐标一致）
runlog [jobN] <cmd...> 异步带日志执行（不入 instances；完成看 .exit）
shell / shell <slot> "cmd" 开可见 cmd 入表 / 往壳粘贴命令
script <名> 启动 %AHK_DIR%\名.ahk

ahk.ps1 函数

函数 作用

5. 实例表（slot）要知道的几件事

双开同名应用时，进程名分不清「第几个」。listener 在每次经文件桥启动时登记一行，主键是 slot（如 wechat#1）。

字段 含义
slot pro + # + 序号，大小写不敏感
pid 进程 ID（kill / close）
hwnd 主窗口（focus / click / close）
exe 实际进程名，如 Weixin.exe
pro 短名：优先快捷方式名（WeChat.lnk → wechat），否则 exe 名
ts 登记时间

只有经 bridge 的普通启动（run / lnk / script / shell / 路径）才会入表。 桌面手动开、runlog（含其中再 start 的进程）都没有 slot。shell 的 pro 固定为 shell（shell#1…），exe 为 cmd.exe。

其它要点：

  • pro 跟捷径文件名走：叫 weixin.lnk 则是 weixin#N，与 exe 是否叫 Weixin.exe 无关。
  • .lnk 指向 .ahk 时，入表的是 AutoHotkey 解释器进程，pro 仍用捷径名。
  • standby_dub_wechat.ahk 自己连开两次微信：listener 只登记脚本进程一条；要 wechat#1/#2，请对 WeChat.lnk 经 bridge 启动两次。
  • 单实例应用第二次启动若没有新进程，可能绑不到新 slot。
  • 死进程约每 5 秒刷 status（或主动 status）时 GC；kill/close 成功也会立刻删表项。

6. 排错

现象 怎么处理
last_result 不更新 桌面是否已登录？listener.ahk 是否在跑？
有 pid= 无 slot= 单实例，或绑窗超时；用 ahk.bat / Wait-AhkResult 等到非 PEND
slot not found 进程已退，或不是经 bridge 启动的
close 后 dead=0 改用 kill（提权进程试 admin kill）
仍停在 PEND| 绑定窗口可能要数秒；勿固定 Sleep 3 就读
runlog 无 .exit / 提示 still running 命令仍在跑（如 npm start）；稍后 type jobs\<id>.exit，或改用 shell / start 启常驻服务
shell 粘贴无反应 桌面 CMD 是否被挡住；看 last_result 是否 typed=1；可先 focus shell#1 再试
kill shell#N 后 node 仍在 命令若用了 start 脱离控制台则杀不干净；应在壳里直接跑服务
runlog 后 instances 无变化 正常：runlog 不登记 slot；常驻要 slot 用 shell
要看 runlog 是否成功 读 jobs\<id>.exit（0=成功）；last_result 只有 spawned，不含最终 exit

附录 A：文件约定

路径 方向 作用
C:\ahk_trigger\command.txt 你 → AHK 写入一条指令（AHK 读完会删）
C:\ahk_trigger\paste.txt 你 → AHK 粘贴正文（UTF-16 LE）；cursor:paste / cursor:send / shell:<slot>（无 | 时）读取
C:\ahk_trigger\last_result.txt AHK → 你 最近一次执行摘要
C:\ahk_trigger\status.txt AHK → 你 桌面状态（约每 5 秒）+ 实例摘要
C:\ahk_trigger\instances.txt AHK → 你 完整实例表（UTF-16 LE）
C:\ahk_trigger\jobs\<id>.log / .exit AHK → 你 runlog 输出与退出码
C:\ahk_trigger\ahk.bat / ahk.ps1 本机助手 前置库

附录 B：原始命令协议（写入 command.txt）

前置库最终写成这些字符串；排查或手写时对照即可。

内容 含义
notepad.exe / 完整路径 / .lnk 普通启动（成功则入实例表）
admin:notepad.exe 提权启动（依赖本机 UAC 等设置）
status 立即刷新 status.txt 并 GC
focus:wechat#2 按 slot 激活
click:wechat#2|140|520 激活后点击；坐标相对窗口左上角（非 Client）
cursor:focus / cursor:agent / cursor:new 激活 Cursor 主窗 / Ctrl+I / 新 Agent 会话
cursor:paste / cursor:paste:submit 读 paste.txt 进剪贴板后 ^v（可选 Enter）
cursor:send / cursor:send:new focus + Agent + 粘贴发送；send:new 点顶部输入框并用 Ctrl+Enter 提交
cursor:stop Esc
close:wechat#1 软关（WinClose，约 3 秒内退出则删表）
kill:notepad#1 硬关（taskkill /F /T 进程树）；提权用 admin:kill:...
shell / admin:shell 开可见 cmd /k，入表 shell#N
shell:shell#1|npm start focus 该壳，粘贴命令并 Enter
shell:shell#1 同上，正文来自 paste.txt
runlog:job1|dir C:\ 异步执行；立刻 spawned；结束后写 jobs\job1.exit（不入 instances）
admin:runlog:job2|whoami 提权 + 同上

listener 一受理就先写 PEND|...|pending|命令，做完再写成 OK/ERR。应等到首字段不是 PEND。runlog 的 OK 表示已拉起（含 spawned pid=），最终退出码只在 .exit。

附录 C：实例表如何生成（细节）

  1. 启动前快照该 exe 已有 PID。
  2. Run 后做差集得新 PID（优先已有主窗口的进程，避免 Win11 记事本「启动器 PID」）。
  3. 等该 PID 主窗口（可见面积最大者）→ hwnd。
  4. 分配最小空闲序号 → pro#N，写入 instances.txt。
  5. last_result 带回 slot= / pid= / hwnd=。
