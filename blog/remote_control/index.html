远程控制总览

家里 Win11 当被控端，外出用 Windows 电脑或 Android 手机当控制端，通过 Tailscale + OpenSSH 远程开发与 Agent 对话；需要 GUI 时可叠加 Parsec 或 Chrome Remote Desktop。

详细步骤已拆成两份文档，按角色查阅即可：

文档角色内容
remote_controled被控端（家里 Win11）OpenSSH、本地账户、电源策略、Tailscale、公钥、桌面主机端、Cursor CLI
remote_controling控制端（外出设备）Remote-SSH Agent 面板、SSH + agent CLI、Termius；Tailscale 与桌面客户端

链路一览

Agent 全程走 SSH 隧道：控制端连上被控端后，在远程跑 agent（终端）或通过 Remote-SSH 开 Agent 面板（图形）。不需要 Worker 常驻进程。

场景速查

场景被控端开什么控制端用什么
笔记本 + Agent 图形对话OpenSSH + Tailscale + Cursor CLICursor Remote-SSH → Agent 面板
终端 Agent / 脚本派活同上ssh home-win → agent / agent -p
手机看输出、发短指令同上Termius → agent 或 tmux attach
敲命令 / 看日志OpenSSH + Tailscalessh / Termius
全图形桌面Parsec 或 CRD + Tailscale对应客户端

部署顺序

  1. 先在被控端完成 remote_controled §1–§6（SSH + Tailscale + 电源），记下 Tailscale IP。
  2. 再完成 §7 Cursor CLI：agent login，本地跑 agent -p "hello" 验证。
  3. 然后在控制端按 remote_controling 接入：笔记本用 Remote-SSH，终端/手机用 ssh + agent。
  4. 可选：配置 SSH 公钥免密，Windows 与 Android 可共用同一密钥。

容易翻车的小点

家里 Win11 睡了 = 全断：Tailscale + SSH 都靠机器醒着，被控端电源策略先看牢。

Microsoft 账号直登 SSH 不通：被控端一定走本地账户或另建 dev 用户，见 remote_controled §2。

Tailscale 连不上先查 DERP：两设备都在 NAT 后大概率能打洞直连，打不通会走 Tailscale 中继（DERP），免费版也够用。管理后台 Machines 页能看到 Direct 还是 Relay。

运营商如果是 CGNAT 也无所谓：Tailscale 本来就不依赖公网 IP，这也是它比端口映射省事的地方。

agent 跑不起来：被控端是否 agent login 过？PATH 是否含 %USERPROFILE%\.local\bin？见 remote_controled §7。

SSH 断了 Agent 也断了：长跑任务用 tmux，见 remote_controling §4 方式 B。
